# Архитектура

Проект организован по функциональности. Внутри `features/characters` выделены domain, data и presentation.

## Слои

| Каталог | Ответственность |
| --- | --- |
| `app` | Конфигурация, сборка зависимостей и жизненный цикл приложения |
| `core/async` | Отмена операций и ожидания без зависимости от HTTP-клиента |
| `core/network` | HTTP-транспорт, повторы запросов, преобразование сетевых ошибок |
| `domain` | Сущности, параметры запроса, контракт репозитория, use case и объединение страниц |
| `data` | API-сервис, DTO, мапперы и реализация репозитория |
| `presentation` | Cubit, состояния, страницы, навигация, форматирование и виджеты |

Domain не зависит от Flutter, Dio и схемы JSON. Presentation обращается к domain, а реализации data подключаются в composition root. Общие механизмы core не зависят от фич.

## Зависимости

`AppDependencies` создаёт Dio, `ApiClient`, `CharactersApiService`, `CharactersRepositoryImpl` и `GetCharacters`. Объекты передаются через конструкторы. `AppBootstrap` закрывает Dio; `CatalogScope` создаёт Cubit через `BlocProvider`, который закрывает его при удалении из дерева.

Поток запроса: виджет → Cubit → GetCharacters → CharactersRepository → CharactersApiService → ApiClient. Сервис разбирает ответ в DTO; маппер преобразует DTO в доменные сущности.

## Поиск и пагинация

Поиск использует debounce 350 мс. Смена запроса отменяет предыдущую операцию и увеличивает номер поколения. Ответ применяется только к актуальному поколению, даже если транспорт не успел обработать отмену.

Следующая страница определяется по `info.next`. `CharacterPagination` объединяет карточки по id, сохраняет порядок и прекращает загрузку при пустом ответе или нерастущем курсоре. Сбой догрузки сохраняет существующие карточки.

## Ошибки и отмена

`ApiException` содержит HTTP-контекст внутри data-слоя. Репозиторий преобразует его в типизированный `AppFailure`; текст сообщения выбирается в presentation. API-специфичный 404 `There is nothing here` означает пустой результат.

Временные сбои GET повторяются максимум два раза. При 429 пауза увеличивается; числовой Retry-After учитывается с пределом 30 секунд. Отмена прерывает как запрос, так и ожидание повтора. Слушатели и таймеры освобождаются после завершения операции.

## Интерфейс и тестирование

Страница каталога владеет контроллерами и обработчиками. Поиск, фильтры, сетка, скелетоны, refresh control и состояния вынесены в отдельные виджеты. Каталог и детали используют общие карточки, изображения и форматтеры. Размеры карточек и скелетонов вычисляются одним layout-классом.

Тесты разделены на core, domain, data и presentation. Для бизнес-логики используется fake-репозиторий, для репозитория — подменный источник данных, для сетевой цепочки — HTTP-адаптер. Архитектурные тесты проверяют направление import/export между слоями.
